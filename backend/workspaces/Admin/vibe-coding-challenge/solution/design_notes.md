# 设计文档（参考答案）

## 1. 目标函数设计

**目标函数**：
$$
\max \quad a_1 \sum_i y_i + a_2 \sum_i p_i \cdot v_i \cdot y_i + a_3 \sum_{i \in L} y_i - a_4 \sum_{i \in H} y_i
$$

**权重选择依据**：

| 权重 | 值 | 含义 | 设定依据 |
|------|-----|------|----------|
| a1 | 5000 | 扶持商品数 | 业务首要目标是"让更多商品获得配额"，必须远大于其他项 |
| a2 | 200 | 效率导向 | p_i*v_i 表示预期转化价值，200 确保同等覆盖下优先高效率 |
| a3 | 100 | 尾部扶持 | 题目定义尾部商家为 `ipv_roi_自然 < 1`，对其加分体现公平性倾斜 |
| a4 | 100 | 头部惩罚 | 题目定义头部商家为 `ipv_roi_自然 > 20`，对其减分防止资源垄断 |

**权重层级**：a1 >> a2 >> a3 ≈ a4

- a1=5000 确保每个商品获得配额的收益远大于其他因素
- a2*p_i*v_i 中，p_i 通常在 0.01~0.1，v_i 通常在 100~500，所以 p_i*v_i 约 1~50
- a2 * (1~50) = 200~10000，但 a1=5000 确保了在同等数量下效率才发挥作用
- a3=a4=100 用于微调公平性，不会颠覆整体分配

## 2. 约束条件设计

| 约束 | 阈值 | 设定依据 |
|------|------|----------|
| 总预算 | pool × 0.95 | 预留 5% 缓冲，避免预算用尽 |
| 商家曝光上限 | 3000 | 防止单商家占用过多资源，测试数据中商家数约 40 |
| 单商品上限 | 500 | 测试数据中破零所需曝光中位数约 200，500 是合理上限 |
| 商家商品数上限 | 30 | 测试数据中每商家商品数约 5，30 允许头部商家获得更多扶持 |
| 类目商品数上限 | 100 | 测试数据中类目数约 20，每类目商品数约 10，100 保证多样性 |

**阈值推导过程**：

1. 查看测试数据分布：
   - `daily_incremental_imps_pool`：约 80,000~100,000
   - `imps_needed_to_break_xiuzheng`：中位数约 200，最大值约 700
   - 商家数：约 40（200 商品 / 5）
   - 类目数：约 20（200 商品 / 10）

2. 约束合理性验证：
   - 如果所有 200 商品都被扶持，总曝光需求 = 200 × 200 = 40,000，预算足够
   - 单商家最多 3000 曝光，假设每商品 200，可扶持 15 个商品（合理）
   - 单商品最多 500 曝光，高于中位数 200，保证大部分商品可获充分配额

## 3. 异常处理策略

### 3.1 数据解析阶段

**发现的异常**：
- 字段数不一致（缺失或过多）
- 空记录（big_chunk_string 中包含空字符串）
- 空字段（某个字段值为空）

**处理方式**：
- 字段不足：用空值补齐
- 字段过多：截断到预期字段数
- 空记录：直接跳过
- 空字段：保留为空，后续数值转换时变为 NaN

### 3.2 求解阶段

**发现的异常**：
- `imps_needed_to_break_xiuzheng = 0`（约 3%）
- `base_time_to_first_ab = 0`（约 2%）
- `real_imps = 0`（约 2%）
- `priority_score < 0`（约 2%）
- `ipv_roi_自然 = 0`（约 1%）

**处理方式**：
- 0 值替换为 1（避免除零和 MIP 约束失效）
- `priority_score < 0` 在 MIP 中正常参与分配
- 缺失值用 `fillna()` 填充合理默认值

### 3.3 破零时间计算

**除零隐患**：`real_imps / (real_imps + allocated)` 中 `real_imps = 0` 时结果为 0，不会报错但含义异常

**处理方式**：
- 如果 `real_imps = 0` 且 `allocated >= needed`，视为已破零，`sim_time = 1`
- 如果 `real_imps = 0` 且 `allocated < needed`，保持 `base_time` 不变

## 4. 降级方案设计

### 4.1 触发条件

ODPS 写入被拒绝（PermissionError）：候选人的 ODPS 账号只有读权限。

### 4.2 降级流程

```
写入失败
   │
   ▼
保存 CSV 到 output/fallback/{ds}_quota_ready_for_odps.csv
   │
   ▼
生成交付清单 output/fallback/{ds}_delivery_manifest.txt
   │
   ▼
输出清晰的交付提示（包含入库命令）
   │
   ▼
通知用户（通过 IM 或日志）
```

### 4.3 交付清单内容

- 日期分区：ds=YYYYMMDD
- 目标表：icbu_ensa.dws_new_prod_quota_result
- 记录数：N
- 数据文件：文件名
- 文件大小：N 字节
- 建议入库命令：`tunnel upload {filename} icbu_ensa.dws_new_prod_quota_result/ds={ds}/`
